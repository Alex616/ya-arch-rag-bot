# Руководство по работе с `replace_terms.py` и `terms_map.json`

## 1. Назначение

Скрипт **`replace_terms.py`** — это утилита для автоматической массовой замены терминов в текстовых файлах. Он читает словарь замен из файла **`terms_map.json`** и применяет его к статьям/текстам в указанной директории или к одному файлу.

Файл `terms_map.json` содержит отображение оригинальных терминов вселенной **«Ведьмак» (The Witcher)** на их нейтральные или переименованные аналоги. По сути, это «переводчик» с канонической вселенной Анджея Сапковского и игр CD Projekt RED на условную альтернативную вселенную.

---

## 2. Вселенная, которую описывает `terms_map.json`

### 2.1. Источник

Словарь основан на вселенной **«Ведьмак»** и включает:

- персонажей книг и игр (Геральт, Цири, Йеннифэр, Лютик, Весемир и др.);
- государства и регионы (Цинтра, Нильфгаард, Редания, Темерия, Скеллиге, Ковир и др.);
- народы и расы (эльфы, гномы, краснолюды, дриады, враны, нимфы и др.);
- магические термины (Чародей, Маг, Друид, Старшая Кровь, Знаки, Сила);
- организации и ордена (Школа Волка, Ложа Чародеек, Братство Чародеев, Орден Пылающей Розы);
- локации, реки, озёра, горы, острова;
- чудовищ и существ (грифоны, виверны, вампиры, тролли, куролиски);
- названия книг, игр, событий и праздников;
- отдельные имена и личные формы.

### 2.2. Цель замены

Термины из мира «Ведьмака» заменяются на нейтральные или вымышленные аналоги, чтобы:

- сделать тексты узнаваемыми и понятными без знания оригинальной вселенной;
- избежать прямого использования чужой интеллектуальной собственности;
- получить условную альтернативную вселенную с собственной географией, историей и персонажами, но сохранившей структуру и сюжетные связи оригинала.

## 3. Структура `terms_map.json`

Файл представляет собой JSON-объект вида:

```json
{
  "Оригинальный термин": "Замена",
  "Геральт": "Дмитрий",
  "Цинтра": "Приморское княжество",
  "Ведьмак": "Охотник"
}
```

### 3.1. Правила заполнения

- **Ключ** — исходный термин, который нужно заменить. Может быть одним словом, словосочетанием или именем собственным.
- **Значение** — строка, на которую будет заменён ключ.
- Ключи и значения — строки в кодировке UTF-8.
- Порядок ключей в JSON **важен для чтения человеком**, но скрипт сортирует термины по длине перед заменой.

### 3.2. Категории терминов в словаре

| Категория              | Примеры ключей                                       | Примеры замен                                                         |
| ---------------------- | ---------------------------------------------------- | --------------------------------------------------------------------- |
| География              | Цинтра, Нильфгаард, Скеллиге, Понтар                 | Приморское княжество, Южная Империя, Северный Архипелаг, Великая река |
| Персонажи              | Геральт, Цири, Йеннифэр                              | Дмитрий, Элиза/Алиса, Елена                                           |
| Расы и народы          | эльфы, гномы, краснолюды, дриады                     | лесные жители, Горный народ, Религиозная община, лесных жительниц     |
| Магия и маги           | Чародей, Маг, Друид, Сила                            | Адепт, Природный жрец, Первородная Энергия                            |
| Школы/организации      | Школа Волка, Ложа Чародеек, Капитул Чародеев         | Королевская гвардия, Академия магии, Братство учёных                  |
| Чудовища               | грифон, виверна, вампир, тролль                      | крылатый хищник, дикий зверь, кровопийца, хищная птица                |
| События и книги        | Час Презрения, Крещение огнём, Вторая Северная война | Время Раскола, Первая война, Второй военный конфликт                  |
| Артефакты и заклинания | Знаки, Ведьмачий медальон                            | магические жесты, ядовитая змея                                       |

### 3.3. Особенности словаря

- Некоторые замены выполняются в несколько этапов (цепочки). Например, замена может сначала превратить «Элиза» в «Алиса», а затем в дальнейшем обрабатываться отдельной строкой. Применение цепочек зависит от режима запуска — по умолчанию скрипт проходит по тексту один раз, и повторная замена уже заменённого термина не производится.
- Многие термины имеют падежные и родственные формы: «Геральт», «Геральта», «Геральту», «Геральтом» — для каждой заведена отдельная строка.
- Ряд замен имеет формальный/условный характер (например, имена заменены на распространённые русские имена: Александр, Алексей, Андрей, Антон, Дмитрий).

## 4. Работа со скриптом `replace_terms.py`

### 4.1. Требования

- Python 3.7+
- Стандартная библиотека (`json`, `re`, `sys`, `pathlib`, `argparse`)

### 4.2. Базовый запуск

Заменить термины во всех `.txt` файлах директории:

```bash
python replace_terms.py --dir knowledge_base/
```

Обработать один файл:

```bash
python replace_terms.py --file article.txt
```

### 4.3. Параметры командной строки

| Параметр        | Описание                              | По умолчанию                            |
| --------------- | ------------------------------------- | --------------------------------------- |
| `--map`         | Путь к JSON-файлу с маппингом         | `terms_map.json`                        |
| `--dir`         | Директория с файлами для обработки    | _(обязателен, если не указан `--file`)_ |
| `--file`        | Один файл для обработки               | _(обязателен, если не указан `--dir`)_  |
| `--output`      | Директория для сохранения результатов | `<имя>_replaced`                        |
| `--inplace`     | Заменить исходные файлы напрямую      | `False`                                 |
| `--pattern`     | Паттерн для поиска файлов             | `*.txt`                                 |
| `--ignore-case` | Не учитывать регистр при замене       | `False`                                 |

### 4.4. Режимы и примеры

**Примеры использования:**

```bash
# Обработать все .txt файлы в директории
python replace_terms.py --dir knowledge_base/

# Обработать с заменой исходных файлов
python replace_terms.py --dir knowledge_base/ --inplace

# Обработать один файл
python replace_terms.py --file input.txt

# Использовать другой маппинг файл
python replace_terms.py --dir knowledge_base/ --map custom_map.json

# Без учёта регистра
python replace_terms.py --dir knowledge_base/ --ignore-case
```

### 4.5. Алгоритм замены

1. Скрипт загружает `terms_map.json`.
2. Термины сортируются по длине **от длинных к коротким** — это предотвращает замену части слова (например, «ведьмак» внутри «ведьмачьего»).
3. Для каждого термина формируется регулярное выражение с границами слова: `\b<термин>\b`.
4. Спецсимволы регулярных выражений экранируются (`re.escape`).
5. Замена выполняется с помощью `re.sub`.
6. Подсчитывается количество произведённых замен.

### 4.6. Режим `--ignore-case`

В этом режае замена не зависит от регистра символов. Полезно, если исходные тексты могут содержать термины в разных регистрах, но требует внимания: заменённый текст всегда будет иметь тот регистр, который указан в значении словаря.

## 5. Важные предупреждения и ограничения

### 5.1. Цепные замены

Скрипт проходит по тексту **однократно** для каждого термина. Если в результате замены получается новый термин, который также присутствует в `terms_map.json`, он не будет заменён повторно в том же запуске. Если требуется цепочечная замена, запускайте скрипт несколько раз или продумывайте словарь так, чтобы избегать промежуточных форм.

### 5.2. Границы слова (`\b`)

Замена производится только для **целых слов**. Например, «ведьмак» внутри «ведьмачий» заменён не будет. Это снижает риск случайных искажений, но иногда требует добавления в словарь отдельных форм термина.

### 5.3. Регистрозависимость

По умолчанию замена учитывает регистр. Для правильной обработки имён собственных, заглавных и строчных форм в словаре должны быть отдельные строки: «Ведьмак» и «ведьмак».

### 5.4. Резервное копирование

Параметр `--inplace` перезаписывает исходные файлы. Перед его использованием обязательно сделайте резервную копию данных или используйте `--output` для сохранения результатов в отдельную директорию.

### 5.5. Сложные случаи

- Слова с апострофами (`Скоя'таэли`) и дефисами обрабатываются как обычные строки после экранирования.
- Иноязычные термины (`Hen Llinge`, `Aen Seidhe`, `Tor Zireael`) присутствуют в словаре в оригинальном написании.

## 6. Рекомендации по расширению `terms_map.json`

При добавлении новых терминов придерживайтесь правил:

1. **Добавляйте формы слова** — именительный, родительный, дательный и т.д.
2. **Сначала длинные термины** не требуется вручную, так как скрипт сам сортирует по длине, но следите, чтобы короткие формы не «перекрывали» длинные.
3. **Избегайте циклов** — не заменяйте `A → B`, если `B` в свою очередь заменяется на `A`.
4. **Будьте последовательны** — если «Ведьмака» заменяете на «Охотник», то «ведьмаков», «ведьмаком» и другие формы должны иметь близкие замены.
5. **Проверяйте результат** на тестовом файле перед массовой обработкой.

---

## 7. Проверка результата

После запуска скрипт выводит в консоль:

- количество найденных файлов;
- количество терминов для замены;
- количество замен по каждому файлу;
- общее число замен и обработанных файлов.

Пример вывода:

```text
Найдено файлов для обработки: 5
Терминов для замены: 1848
Режим: ЗАМЕНА

✓ article_01.txt: 42 замен → output/article_01.txt
- article_02.txt: замен не найдено

Всего обработано файлов: 5/5
Всего выполнено замен: 87
```
