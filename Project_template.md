# Анализ задачи

## Описание задачи

Разработать интелектуального бота, который должен быстро и точно давать персонализированные ответы на вопросы сотрудников на основе базы знаний, выявлять пробелы в документации и помогать системно улучшать её качество. Такого бота, применяя технологии Retrieval-Augmented Generation (RAG) и продвинутые техники промптинга для улучшения ответов, вам и нужно создать.

### Цели бизнеса в контексте внедрения RAG-бота

1. Сократить затраты на поиск информации и коммуникацию внутри команды.
2. Повысить продуктивность сотрудников.
3. Автоматизировать повторяющиеся операции и запросы.
4. Выявить и устранить пробелы в корпоративной документации.
5. Улучшить качество внутренних процессов и знаний.
6. Создать масштабируемое решение, которое можно будет переиспользовать.
7. Поддерживать рост и устойчивость бизнеса.

### Технологии используемые в разработке:

- python 3.11
- векторная бд (faiss, chromadb и тп)
- бот должен работать как бот telegram

## Характеристики компании

### Функции и роли пользователей базы знаний:

- Разработчики ищут архитектурные решения, API-документацию и описание микросервисов.
- Саппорт ищет способы решения типовых проблем пользователей.
- Менеджеры и аналитики — регламенты и бизнес-правила.
- Новые сотрудники — onboarding-инструкции.

### Проблемы:

- Разрозненность и дубли. База знаний растёт, но плохо структурирована и слабо покрывает реальные запросы. Одни и те же процессы описаны в Confluence, Notion и PDF-регламентах, но расходятся по версиям. При этом руководство не может объективно оценить, что в документации действительно важно, а что требует доработки.
- Время поиска. Новые инженеры тратят до четырёх часов в неделю, чтобы «раскопать» нужное решение (это следует из данных опроса HR-отдела), а одни и те же вопросы часто задаются повторно.
- Жизненный цикл контента. У страниц нет единого владельца, поэтому после релиза очередного major-release документация устаревает через 2-3 месяца.
- Соответствие аудитам: подготовка к SOC 2 yearly review занимает около 140 часов работы GRC-команды из-за ручной сверки актуальных политик.

### Статистика

- ≈ 18 000 Markdown/MDX файлов в репозиториях.
- ≈ 3 000 страниц Confluence (30 пространств).
- ≈ 250 PDF‑спецификаций (наследие заказных проектов).
- Объём прироста — примерно 400 страниц в месяц.

### Конфигурация сервера

#### Вариант 1: API-based (YandexGPT + Yandex Embeddings + ChromaDB)

| Ресурс | Значение | Комментарий |
| ------ | -------- | ----------- |
| CPU    | 4-8 ядер | Достаточно для обработки запросов Telegram бота и работы ChromaDB |
| RAM    | 8-16 GB  | 4GB для ChromaDB с индексом ~21K документов + 4GB для приложения и ОС |
| GPU    | Не требуется | Все вычисления через API Yandex |
| Диск   | 50-100 GB SSD | Для хранения векторной БД, логов, кэша |

Примерная стоимость VPS: ~3000-5000₽/мес (Yandex Cloud, VK Cloud)

#### Вариант 2: Hybrid (YandexGPT API + CPU эмбеддинги + ChromaDB)

| Ресурс | Значение | Комментарий |
| ------ | -------- | ----------- |
| CPU    | 8-16 ядер | Для генерации эмбеддингов локально (multilingual-e5-large) |
| RAM    | 16-32 GB | 8GB для модели эмбеддингов + 4GB для ChromaDB + 4GB для приложения |
| GPU    | Не требуется | Эмбеддинги на CPU, LLM через API |
| Диск   | 50-100 GB SSD | Для модели (~2GB), векторной БД, данных |

Примерная стоимость VPS: ~5000-8000₽/мес

#### Вариант 3: Self-hosted (CPU LLM + CPU эмбеддинги + ChromaDB)

| Ресурс | Значение | Комментарий |
| ------ | -------- | ----------- |
| CPU    | 16-32 ядра | Для запуска Qwen2.5-3B + эмбеддинги. Ответ генерируется 20-30 сек |
| RAM    | 32-64 GB | 8GB для LLM + 8GB для эмбеддингов + 8GB для ChromaDB + буфер |
| GPU    | Не требуется | Все на CPU, но медленно |
| Диск   | 100-200 GB SSD | Для моделей (~5GB), векторной БД, кэша |

Примерная стоимость VPS: ~12000-20000₽/мес

#### Вариант 4: GPU-based Self-hosted (полностью локально)

| Ресурс | Значение | Комментарий |
| ------ | -------- | ----------- |
| CPU    | 8-16 ядер | Для обработки запросов |
| RAM    | 32-64 GB | Для загрузки моделей и обработки данных |
| GPU    | NVIDIA RTX 3090 / A4000 (24GB VRAM) | Для Saiga-Llama3-8B + эмбеддинги одновременно |
| Диск   | 100-200 GB NVMe SSD | Для моделей, БД, данных |

Примерная стоимость: ~50000-80000₽/мес (аренда GPU-сервера) или покупка железа ~200000₽

**Выбранный вариант**: **Вариант 1 (API-based с YandexGPT + Yandex Embeddings + ChromaDB)**

**Обоснование:**
1. Оптимальное соотношение цена/качество для русского языка
2. Быстрый запуск и простая поддержка
3. Общая стоимость ~11000-17000₽/мес (VPS + API) приемлема для бизнеса
4. Данные остаются в РФ (важно для корпоративной документации)
5. Быстрые ответы (1-3 сек) обеспечивают хороший UX
6. Легко масштабируется при росте нагрузки
7. Не требует ML-экспертизы в команде

**План миграции (опционально):**
- Если API-затраты вырастут >30000₽/мес, можно мигрировать на Вариант 4 (GPU)
- Для MVP можно начать с Вариант 2 (Hybrid) с бесплатными эмбеддингами на CPU
